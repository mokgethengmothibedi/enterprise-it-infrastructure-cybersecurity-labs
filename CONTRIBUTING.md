# Documentation and Evidence Guidelines

This repository is a personal learning portfolio. Documentation should preserve accuracy, reproducibility and safe lab practices.

## Evidence standards

- Separate planned work, implementation and validated results.
- Never invent command output, screenshots, users, groups, shares or test results.
- Include the environment and date for each test.
- Explain commands and configuration choices.
- Record failures, root causes and remediation.
- Redact credentials, tokens, recovery keys, real personal data and unrelated network information.

## File organisation

Keep project-specific evidence under the relevant project folder. Use the scenario report template for each practical exercise. Use descriptive filenames such as WIN-07-dns-dc-discovery.md.

## Safety

Only test systems and networks that you own or are authorised to assess. Keep security simulations benign and isolated to the lab.
